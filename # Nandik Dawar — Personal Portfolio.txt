# Nandik Dawar — Personal Portfolio Website

## Project Brief

Build a polished, production-ready personal portfolio website for **Nandik Dawar**, a Full Stack Developer and Computer Science student.

The portfolio should feel:

- Modern
- Colourful
- Creative
- Professional
- Developer-focused
- Friendly and approachable
- Visually distinctive
- Smooth and premium
- About **80% creative/product-design aesthetic**
- About **20% software-engineering aesthetic**

The website must **NOT** look like a stereotypical developer portfolio with:

- Black backgrounds everywhere
- Green terminal text
- Excessive neon
- Matrix effects
- Giant code editors
- Cyberpunk visuals
- Excessive glassmorphism
- Overdone 3D effects
- Gaming-style UI

The primary inspiration is the visual structure and polish of:

`https://www.rubenmarcus.dev/`

However, do **not** copy the website.

Use it only as inspiration for:

- Strong typography
- Section transitions
- Portfolio storytelling
- Visual hierarchy
- Motion
- Project presentation
- Premium feel

The final website should use the colourful design direction provided in the reference mockups.

---

# 1. Core Design Direction

The visual identity should use:

- Warm cream/off-white background
- Coral/orange accents
- Royal blue accents
- Soft purple accents
- Mint/teal accents
- Occasional yellow
- Dark navy/charcoal typography

The overall visual feeling should resemble:

> Creative product designer portfolio meets modern software engineer portfolio.

The website should communicate that Nandik is someone who:

- Builds real products
- Understands backend systems
- Works with cloud technologies
- Builds full-stack applications
- Works with APIs
- Has experience with AI/computer vision
- Understands testing and automation
- Can design complete systems

---

# 2. Primary Technology Stack

Use the following stack.

## Frontend

- Next.js
- TypeScript
- React
- Tailwind CSS

Use the latest stable versions.

Prefer the **Next.js App Router** architecture.

---

## Animation

Use:

- Motion / Framer Motion for standard animations
- GSAP only when Motion cannot cleanly implement an effect
- Lenis for smooth scrolling

Do not unnecessarily use GSAP everywhere.

Motion should handle approximately 80–90% of animations.

## Icons

Use:

- Lucide React

Do not mix several icon libraries.

---

## Contact Form

Use:

- Next.js API route / Server Action
- Resend

The form should send contact messages to the portfolio owner's email.

```text

```

rotate slightly on hover.

Cursor blink animation.

# 64. Avoid

Do NOT add:

- Full screen 3D objects
- Three.js unless genuinely required
- Particle backgrounds
- Matrix effects
- Heavy shaders
- Constant mouse-follow effects
- Excessive parallax
- Auto-playing videos
- Autoplay music
- Huge loading animations
- Excessive glass blur
- Horizontal scrolling that breaks mobile usability

---

# 67. Content Source of Truth

Portfolio content should be based on the supplied resume.

- Certifications
- Employment
- Project achievements
- Technologies
- Awards

# 71. Cursor / Motion Accessibility

When:


- Smooth scrolling
- Large transitions
- Floating animations
- Cursor effects
